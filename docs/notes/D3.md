# D3: progressive distillation

`methods/progressive.py`, registered as `progressive`. Configs: `image_flow_progressive.yaml`, `image_ddpm_progressive.yaml`.

## Design

- Rounds: round r trains the student on an N_r = start_steps / 2**(r+1) step grid to match two ODE steps of the round's teacher on the 2 N_r grid. `start_steps: 16, rounds: 3` gives 8 -> 4 -> 2 student steps. The grids are nested (the flow shift is applied pointwise to a linspace), so the midpoint is `teacher_grid[2k+1]`.
- Round 0's teacher is the real teacher, with `teacher_guidance`. At each round boundary `schedule` copies the EMA student into a frozen `round_teacher` (the SDTT pattern), used with guidance 1. The student keeps training from its current weights; the optimiser is not reset.
- `default_grid` returns the last round's grid, so `tr.grid` and the exported `sampling.timesteps` are the 2-step grid. Setting `student_steps` would override that; the configs do not.
- Target, from `alpha_sigma` only: x_t and x_s are both a x0 + sigma eps, so the (x0, eps) whose one ODE step from t lands on the two-step result x_s* is eps* = (a_s x_t - a_t x_s*)/(a_s sigma_t - a_t sigma_s), x0* = (sigma_t x_s* - sigma_s x_t)/(sigma_t a_s - sigma_s a_t). `target_pred` maps this to the network output (eps for gaussian, velocity for flow) using that `to_eps` is affine in pred. For the gaussian case this is the paper's x0 target.
- Loss: MSE in x0 space against x0*, for both processes, weighted by max(SNR, 1) (`weighting: none` disables it).
- No trainer change.

## Review patches

- `target_pred` converts through `to_x0` (nonzero slope for t > 0) instead of `to_eps`, which has zero slope at t = 1 for flow. The probe disables the gaussian `clip_x0`. Tested at t = 1 with s = 0 and an interior s.
- `setup` raises if `steps < rounds` or if `student_steps` / `student_timesteps` is set. `tr.grid` is moved to each round's grid in `schedule`, so any export (including `save_every`) carries the grid of the round reached; a full run ends on the 2-step grid. The tiny end-to-end test uses `rounds=2` for these configs.
- At each round boundary the student is re-initialised from the EMA snapshot, and the optimiser state and EMA shadow are reset (as in the paper).
- The gaussian config sets `student_process: {clip_x0: 1.0}`. The loss itself uses the unclipped teacher process.
- The run above was made before the re-initialisation and the target change; it was not repeated.
