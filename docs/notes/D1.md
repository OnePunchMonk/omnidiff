# D1: DMD2 grid mismatch

## Findings

Backward simulation is correct. `DMD2.generate` rolls the student out (renoise sampler, `tr.grid`) to `grid[k]`
with `k` uniform in `0..K-1` (the `last_stage_prob=None` behaviour), then predicts x0 at `t = grid[k]`. The state is the one inference meets at that
grid point, and `k = K` (t = 0) is never drawn. The rollout is `no_grad` as in the DMD2 paper: only the final x0
prediction carries gradient. Tests pin all of this, including a non-uniform grid.

Scorecard: at `nfe == len(grid) - 1` the trained grid is used (`_trained_grid`), so nfe 4 is on-grid. At other
nfe it falls back to `process.timesteps(nfe)`. With `shift = 1` the 4-step grid is 1, .75, .5, .25, 0. The 2-step
grid (1, .5, 0) is a subset of the trained times; 3 steps (.667, .333) and 8 steps (.875, .625, ...) are
untrained times. So the student is a discrete-time model: only 4 values of t are ever trained, and 8 steps
visits times it has never seen. That part is expected, not a bug.

The actual problem is on the trained grid. Per-stage x0 predictions of a 4-step chain (scored against teacher
samples, FD) from the old 600-step run: stage 0..3 = 0.289, 0.159, 0.140, 0.400. Stages 1 and 2 are good; the
last stage, which is the output at inference, is the worst after stage 0, and its FD rose during training
(eval FD at 200/400/600 steps: 0.23, 0.38, 0.42, with diversity creeping up). The DM gradient matches the
mixture of all stages' outputs (and the fake score is fit to that mixture) to the data, while inference
returns only the last stage's. The mixture can match while the last stage drifts. This is a hypothesis
consistent with the per-stage numbers, not isolated by an ablation.

## Change

`DMD2(last_stage_prob=p)`: with probability `p` draw the last stage, otherwise uniform. The last stage's overall probability is `p + (1 - p) / K` (0.625 for K = 4, p = 0.5), since the uniform draw can
also hit it. `p` is validated to be `None` or in [0, 1]. Default `None` keeps the
old behaviour; `configs/distill/image_flow_dmd2.yaml` uses 0.5. Public methods are unchanged.

## CPU check (240 steps, one seed, 256 samples, data FD)

| nfe | uniform stages | last_stage_prob 0.5 |
|---|---|---|
| 1 | 0.433 | 0.587 |
| 2 | 0.335 | 0.348 |
| 3 (off grid) | 0.267 | 0.202 |
| 4 (trained grid) | 0.354 | 0.193 |
| 8 (off grid) | 0.947 | 0.498 |

With uniform stages the best nfe is 3 and the trained grid is worse than 2 and 3. With `last_stage_prob`
the trained grid is best (0.193); 1 step gets worse, expected since stage 0 is drawn less often. 8 steps still
degrades, as the untrained times explain. Single seed and 240 steps, so the margins are not established; the
3-seed runs should confirm.
